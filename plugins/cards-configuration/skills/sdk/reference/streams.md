This document describes stream transform development with `@cards/configuration`.

## Overview

A stream transform is a per-line processing function for JSONL streams attached to cards. Each line passes through the transform before being persisted and broadcast via WebSocket. Transforms run in **isolated `worker_threads` + `vm.SourceTextModule` sandboxes** for crash isolation and security.

## Creating a Stream Transform

### File Structure

Place transform source files alongside other handler sources:

```
my-config/
├── settings.config.ts
├── src/
│   ├── actions/
│   ├── validators/
│   └── transforms/
│       └── my-transform.ts      # Transform source
├── test/
│   └── transforms/
│       └── my-transform.test.ts # Tests against compiled bundle
└── dist/
    ├── settings.json            # Generated by CLI
    └── bin/
        └── my-transform.{hash}.mjs  # Compiled bundle
```

### Transform Module Pattern

Every transform module must default-export the result of `defineStreamTransform`:

```typescript
// src/transforms/my-transform.ts
import type { StreamInitContext, TransformContext } from '@cards/configuration';
import { defineStreamTransform } from '@cards/configuration/factories/stream-transform';

function handleInit(context: StreamInitContext): void {
  // Called once when the stream starts. Seed state here.
  context.state.set('count', 0);
  context.state.set('clientId', context.headers['x-client-id'] ?? 'unknown');
}

function handleTransform(line: string, context: TransformContext): string {
  // Called for each line. Return the transformed line.
  const count = ((context.state.get('count') as number) ?? 0) + 1;
  context.state.set('count', count);

  try {
    const data = JSON.parse(line);
    return `[${count}] ${data.message ?? line}`;
  } catch {
    return line; // Fail-open: return original on parse error
  }
}

export default defineStreamTransform(
  {
    streamType: 'my-stream',
    sourcePath: typeof URL !== 'undefined' ? new URL(import.meta.url).pathname : undefined,
    maxLineLength: 1_048_576  // 1 MB per line
  },
  handleTransform,
  handleInit   // Optional — omit if no initialization needed
);
```

### StreamTransformConfig Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `streamType` | `string` | (required) | Key matching the environment config entry |
| `sourcePath` | `string?` | `undefined` | Path to source file for CLI compilation |
| `maxLineLength` | `number?` | 1 MB | Max bytes per line before truncation |
| `maxStreamSize` | `number?` | 100 MB | Max cumulative bytes before auto-close |
| `timeout` | `number?` | 5000 | Per-call timeout in milliseconds |

### sourcePath Convention

Always provide `sourcePath` so the CLI knows where to find the source for compilation:

```typescript
// Preferred — works in all environments
sourcePath: typeof URL !== 'undefined' ? new URL(import.meta.url).pathname : undefined

// Alternative
sourcePath: import.meta.filename
```

## StreamInitContext Interface

The optional `init()` function receives this context once at stream start:

```typescript
interface StreamInitContext {
  /** Stream type key from configuration. */
  streamType: string;

  /** Stream filename (e.g., "session.log"). */
  filename: string;

  /** HTTP request headers from the POST that created the stream. */
  headers: Record<string, string>;

  /** Card that owns this stream. */
  card: {
    id: string;
    title?: string;
    metadata: Record<string, unknown>;
  };

  /** Mutable state Map shared with all transform() calls in this stream. */
  state: Map<string, unknown>;
}
```

## TransformContext Interface

The `transform()` function receives this context for each line:

```typescript
interface TransformContext {
  /** 1-based line number in the stream. */
  lineNumber: number;

  /** Stream type key from configuration. */
  streamType: string;

  /** Mutable state Map shared with init(). */
  state: Map<string, unknown>;
}
```

## Registering Transforms in settings.config.ts

Import the transform module and pass the command object directly:

```typescript
import { defineConfig } from '@cards/configuration';
import myTransform from './src/transforms/my-transform.js';

export default defineConfig({
  environments: {
    default: {
      version: 1,
      actions: [ /* ... */ ],
      streams: {
        'my-stream': {          // Must match streamType in factory config
          version: 1,
          transform: myTransform  // The imported command object
        }
      }
    }
  }
});
```

## Sandbox Restrictions

Stream transforms run in an isolated VM sandbox. The following are **NOT available** at runtime:

`require`, `process`, `Buffer`, `fetch`, `setTimeout`, `setInterval`, `fs`, `path`, any Node built-in, dynamic `import()`.

All `import` statements in the transform source are resolved and inlined at build time by esbuild. The bundle must be completely self-contained — npm packages that call Node built-ins at runtime will fail in the sandbox.

`console` is available and proxied to the main thread as log messages.

## State Map Lifecycle

1. **Created** fresh in the worker when the stream starts (before `init()`)
2. **Populated** by `init()` with session-level data (counters, caches, parsed headers)
3. **Shared** — the same Map instance is passed to every `transform()` call via `context.state`
4. **Isolated** — lives entirely in the worker thread, never serialized across boundaries
5. **Destroyed** when the stream closes and the worker terminates

Different stream instances never share state Maps.

## Error Handling (Fail-Open)

When a transform throws, times out, or returns a non-string:

1. The **original raw line** is returned unchanged (no data loss)
2. A warning is logged to the server console
3. A `stream:error` event is broadcast to connected clients

Always handle parse errors gracefully inside the transform to produce meaningful output rather than relying on the fail-open fallback:

```typescript
function handleTransform(line: string, context: TransformContext): string {
  try {
    const data = JSON.parse(line);
    return formatData(data);
  } catch {
    return line; // Fallback to original
  }
}
```

## Transform Examples

### Simple Line Prefix

```typescript
import { defineStreamTransform } from '@cards/configuration/factories/stream-transform';

export default defineStreamTransform(
  { streamType: 'logs', sourcePath: new URL(import.meta.url).pathname },
  (line, ctx) => `[${ctx.lineNumber}] ${line}`
);
```

### JSON Pretty-Printer

```typescript
import type { TransformContext } from '@cards/configuration';
import { defineStreamTransform } from '@cards/configuration/factories/stream-transform';

export default defineStreamTransform(
  { streamType: 'json-log', sourcePath: new URL(import.meta.url).pathname },
  (line: string, context: TransformContext): string => {
    try {
      const obj = JSON.parse(line);
      return `**Line ${context.lineNumber}:**\n\`\`\`json\n${JSON.stringify(obj, null, 2)}\n\`\`\``;
    } catch {
      return line;
    }
  }
);
```

### Stateful Session Counter

```typescript
import type { StreamInitContext, TransformContext } from '@cards/configuration';
import { defineStreamTransform } from '@cards/configuration/factories/stream-transform';

function handleInit(ctx: StreamInitContext): void {
  ctx.state.set('count', 0);
  ctx.state.set('sessionId', ctx.headers['x-session-id'] ?? 'unknown');
  ctx.state.set('startTime', Date.now());
}

function handleTransform(line: string, context: TransformContext): string {
  const count = ((context.state.get('count') as number) ?? 0) + 1;
  context.state.set('count', count);
  const sessionId = context.state.get('sessionId') as string;
  return `[Session: ${sessionId}] [#${count}] ${line}`;
}

export default defineStreamTransform(
  { streamType: 'session', sourcePath: new URL(import.meta.url).pathname },
  handleTransform,
  handleInit
);
```

### SDK Message Formatter (Real-World Example)

The `claude-code-session` transform in the default configuration parses Claude Agent SDK messages and formats them as human-readable markdown. It uses `@anthropic-ai/claude-agent-sdk` types (bundled at compile time) and tracks turn count via init state:

```typescript
import type { SDKMessage } from '@anthropic-ai/claude-agent-sdk';
import type { StreamInitContext, TransformContext } from '@cards/configuration';
import { defineStreamTransform } from '@cards/configuration/factories/stream-transform';

function handleInit(context: StreamInitContext): void {
  context.state.set('turn', 0);
}

function handleTransform(line: string, context: TransformContext): string {
  if (!line.trim()) return line;

  try {
    const message = JSON.parse(line) as SDKMessage;

    if (message.type === 'assistant') {
      const turn = (context.state.get('turn') as number) || 0;
      context.state.set('turn', turn + 1);
    }

    switch (message.type) {
      case 'assistant':
        return formatAssistant(message);
      case 'result':
        return formatResult(message);
      default:
        return line;
    }
  } catch {
    return line;
  }
}

export default defineStreamTransform(
  {
    streamType: 'claude-code-session',
    sourcePath: typeof URL !== 'undefined' ? new URL(import.meta.url).pathname : undefined,
    maxLineLength: 1_048_576
  },
  handleTransform,
  handleInit
);
```

## Development Checklist

- [ ] Transform uses `export default defineStreamTransform(config, handler, init?)` pattern
- [ ] `streamType` in factory config matches the key in `settings.config.ts` `streams` object
- [ ] `sourcePath` is provided for CLI compilation
- [ ] Transform handler accepts `(line: string, context: TransformContext)` and returns `string | Promise<string>`
- [ ] Parse errors handled gracefully with try/catch (fail-open)
- [ ] State operations use `context.state.get()` / `context.state.set()`
- [ ] No use of `require`, `fetch`, `setTimeout`, `fs`, `process`, or dynamic `import()` (sandbox rejects them)
- [ ] Run `yarn build` after every code change
- [ ] Tests run against the compiled `.mjs` bundle from `dist/bin/`
- [ ] `vitest.config.ts` sets `testTimeout: 30000` (worker spawning can be slow)
